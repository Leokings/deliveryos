# DeliveryOS audit fixes and verification — 11 October 2026

## Result and scope

The two reproducible findings from the final V5 audit are fixed for the
updated deployment: JSON preflight now matches the on-chain BOM policy, and
new V6 jobs have a guarded recovery path for missing Passport receipts.
No unresolved reproducible review blocker was found in the changed paths
after these checks. This is not a guarantee of steward acceptance, a formal
third-party security audit, or proof that AI judgments cannot be wrong.

## Findings fixed

| Finding | Fix | Verification |
| --- | --- | --- |
| Browser preflight stripped a UTF-8 BOM, accepting JSON that the contract rejected. | Both manifest and artifact decoders preserve the BOM before JSON.parse, which rejects it like Python's UTF-8 JSON path. | Two new regression cases reject BOM JSON even with matching hashes; ordinary canonical packages still pass. |
| A terminal V5 review had only one callback attempt; a failed child transaction could leave its receipt missing. | New immutable V6 source and Passport V2. Only a party can retry a terminal CONSENSUS outcome, with expected version and a 120-second dispatch cooldown. Payload comes solely from stored state. | Normal live callback, controlled failed child then recovered child, unchanged job/submission, recomputed receipt IDs, duplicate no-ops. |
| Switching registries could make older public history disappear. | Public lookup reads both known registries, preserving immutable receipt fields and exposing provenance separately. | Active V6 outcome and original V5 receipt both verified through the live API and browser. |
| Retry scripts could lose a hash when receipt polling hit a gateway error. | The new integration helper logs the hash immediately after a single submission, retries only reads, and supports explicit resume IDs/hashes. | Existing transactions were resumed after HTTP 502s; deployments and evaluations were not repeated. |

## Remaining boundaries, not hidden claims

- Browser job creation and hosted lifecycle REST are V4. V6 lifecycle and
  recovery use the local MCP connector; public Passport lookup is hosted.
- Recovery is explicit and caller-signed, not an autonomous retry worker.
- The API uses a bounded recent recorded window per registry. A late
  recovered decision can be older than previously recorded decisions.
- Profiles are self-reported. Two colluding wallets can manufacture example
  work; receipts are not a reputation, identity, authenticity, or truth score.
- Evidence is public and text-only. No escrow, payments, private evidence,
  arbitrary website execution, or image/video interpretation is claimed.
- A live controlled validator-disagreement/adversarial judgment run and
  third-party agent-host deployment remain unverified. AI decisions can be
  wrong; the failure test covers one callback failure/retry scenario.
